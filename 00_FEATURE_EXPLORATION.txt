CICMalDroid2020 Dataset - Feature Exploration
=============================================

This dataset (`cleaned_dataset.csv`) contains dynamic features extracted from Android applications. The feature set comprises 470 features (plus a `Label` column), representing the frequencies of various system calls, binder interactions, and Android API calls observed during the dynamic analysis of the applications in an isolated sandbox environment.

### 1. Categories of Features

The features can be broadly categorized into the following groups:

A. High-Level Android Behaviors & Permissions
These features map to high-level Android intents, permissions, and behaviors requested or executed by the app. 
Examples:
- `ACCESS_PERSONAL_INFO___`: Attempts to access user data.
- `NETWORK_ACCESS____`, `NETWORK_ACCESS(READ__WRITE)`: Network activity indicators.
- `SMS_SEND____`: Sending SMS messages.
- `FS_ACCESS(READ__WRITE)`: File system read/write attempts.
- `CREATE_PROCESS`, `CREATE_THREAD`, `TERMINATE_PROCESS`: Process management.

B. Native Linux System Calls (Syscalls)
These are raw POSIX system calls executed by the application natively or via standard libraries. Malware often relies heavily on native code (via JNI) to hide its behavior or perform exploits.
Examples:
- File I/O: `open`, `read`, `write`, `close`, `lseek`, `stat64`, `chmod`, `chown32`, `mkdir`, `unlink`.
- Network & Sockets: `socket`, `bind`, `listen`, `accept`, `connect`, `recvfrom`, `sendto`, `sendmsg`.
- Process & Memory: `fork`, `execve`, `clone`, `mmap2`, `mprotect`, `ptrace`, `wait4`.
- System Info: `ioctl`, `sysinfo`, `uname`.

C. Android Framework / API / Binder Calls
These represent specific Android API methods or framework services invoked by the app. Malware uses these to gather intelligence on the device, manipulate settings, or interact with other apps/services.
Examples:
- Device & User Info: `getDeviceId`, `getSubscriberId`, `getAccounts`, `getNetworkInfo`, `getInstalledPackages`, `getSimSerialNumber`.
- Hardware & Sensors: `getCameraInfo`, `getCellLocation`, `getDisplayInfo`.
- System Interaction: `checkPermission`, `setComponentEnabledSetting`, `cancelAllNotifications`, `vibrate`, `requestLocationUpdates`.

### 2. The Target Variable (`Label`)

The final column is the target variable for binary classification.
- `0`: Benign (Original Class 5)
- `1`: Malware (Encompasses Adware, Banking Trojans, SMS Malware, and Riskware)

### 3. Feature Representation

All feature values in this dataset are integers representing the **frequency** (count) of how many times a particular system call or behavior occurred during the dynamic analysis timeframe.
- A value of `0` means the behavior was not observed.
- High values indicate repeated execution, which might represent heavy I/O, network polling, or background service loops.

### Significance for Obfuscation & Explainability (Project Objective)
When a malware author obfuscates an app (e.g., using Obfuscapks to rename variables, encrypt strings, or restructure code), the *static* features change drastically. However, the *dynamic* features (like system calls and API invocations) often remain stable because the app still needs to perform the same underlying operations to achieve its malicious goals.

By analyzing the SHAP values of these dynamic features, we can understand which specific API calls and syscalls the model relies on to detect malware, and test if this reasoning holds true even after the app is obfuscated.
