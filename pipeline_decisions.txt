# Pipeline Decisions & Rationale

This document explains the design rationale behind the 3 model pipelines (Random Forest, XGBoost, and Neural Network) selected for binary Android malware classification, as well as the expected outputs generated by their respective Jupyter notebooks.

## 1. Random Forest Pipeline (`rf_pipeline.ipynb`)
**Why this pipeline was selected:**
- **Role**: Serves as a robust, interpretable baseline ensemble model that inherently handles non-linear relationships.
- **Preprocessing**: None. Tree-based models are scale-invariant, so feature scaling is unnecessary.
- **Hyperparameters**: 
  - `n_estimators=300`: Ensures a stable ensemble that reduces variance.
  - `min_samples_leaf=2`: Adds a slight regularization constraint to prevent overfitting to noisy samples.
  - `class_weight='balanced'`: Critical for adjusting decision tree splits to penalize errors on the minority class (Benign), given the heavily imbalanced dataset (9,803 malware vs 1,795 benign).
  - `n_jobs=-1`: Maximizes training and inference speed using all available CPU cores.

**Expected Code Output:**
- A serialized model (`model.joblib`).
- A null/no-op scaler (`scaler.joblib`) saved for pipeline uniformity.
- JSON files detailing standard metrics (`metrics.json`), inference speed benchmarks for single and batch predictions (`timing.json`), and model footprint/structural complexity like tree depth and node counts (`size.json`).
- A CSV containing test split predictions and probabilities (`test_predictions.csv`).

## 2. XGBoost Pipeline (`xgboost_pipeline.ipynb`)
**Why this pipeline was selected:**
- **Role**: State-of-the-art gradient boosting framework designed for high accuracy and fast execution. Often outperforms Random Forest on structured tabular data.
- **Preprocessing**: None. Like Random Forest, gradient boosting trees do not require feature scaling.
- **Hyperparameters**:
  - `scale_pos_weight`: Dynamically computed from the training split (count of negative class / count of positive class) to mathematically balance the loss function.
  - `max_depth=6` and `learning_rate=0.1`: Standard defaults that provide a good balance between learning capacity and convergence speed.
  - `subsample=0.8` & `colsample_bytree=0.8`: Injects stochasticity to prevent overfitting and improve generalization.
  - `early_stopping_rounds=10`: Prevents over-training by monitoring the validation split and halting when the `logloss` stops improving.

**Expected Code Output:**
- A native XGBoost serialized model (`model.json`).
- A null/no-op scaler (`scaler.joblib`) saved for pipeline uniformity.
- JSON files for metrics (`metrics.json`), timing benchmarks (`timing.json`), and structural complexity measured by tree counts and nodes (`size.json`).
- A CSV containing test split predictions and probabilities (`test_predictions.csv`).

## 3. Neural Network Pipeline (`nn_pipeline.ipynb`)
**Why this pipeline was selected:**
- **Role**: Evaluates the efficacy of deep learning on high-dimensional static features, acting as a contrast to tree-based approaches.
- **Preprocessing**: 
  - `log1p` transformation to compress heavily skewed frequency count features.
  - `StandardScaler` (fitted purely on the training set) to center and scale features. This is strictly required for neural networks to ensure numerical stability, prevent exploding gradients, and ensure smooth convergence.
- **Architecture**:
  - A multi-layer perceptron: `Input(3078) -> Dense(128) -> Dropout(0.4) -> Dense(64) -> Dropout(0.3) -> Dense(1)`.
  - Kept intentionally small (capped at strictly < 500,000 parameters) to prevent the network from blindly memorizing the training data (overfitting), keeping it lightweight and fast.
- **Hyperparameters**:
  - **Loss**: Weighted binary cross-entropy, utilizing dynamically computed class weights to combat the label imbalance.
  - **Callbacks**: `ReduceLROnPlateau` (to dynamically lower the learning rate when validation loss plateaus) and `EarlyStopping` (to halt training and restore the best weights, preventing overfitting).

**Expected Code Output:**
- A serialized Keras model (`model.keras`).
- A serialized `StandardScaler` object (`scaler.joblib`) that holds the exact mean and variance from the training split, required for scaling downstream/obfuscated data.
- JSON files for metrics (`metrics.json`), timing benchmarks including recorded TensorFlow thread usage (`timing.json`), and structural complexity measured by total trainable parameters (`size.json`).
- A CSV containing test split predictions and probabilities (`test_predictions.csv`).
